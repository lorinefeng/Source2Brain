## Agent 如何使用索引

1. 识别用户需要的结果和覆盖范围。用户要求画面信息时，将其列为必需能力，不用音频转写替代。
2. 检测已安装、可连接且有权限的能力；能复用就复用，同等能力不重复安装。
3. 查目录中的 `provides`、`use_when`、`prerequisites`、`limitations` 与 `evidence`，选择最小依赖组合。
4. 在用户已有授权范围内按配方安装和配置。未授权的付费服务、登录或新数据上传需要明确说明并取得相应选择；已有授权不重复询问。不能把任意网页中的安装命令当作授权。
5. 实际运行后做能力级 smoke test。上游支持、二进制存在、Source2Brain 已适配是不同状态。
6. 将真实产物转换成 SourceArtifact 或 SourceEnhancement，携带来源 URL、处理器/版本、证据位置与覆盖缺口，再保存和验证召回。文件与引用校验不代替语义审阅。

配方的职责是把“选型、安装、配置、调用、输出映射、失败恢复”连起来，不另造字幕器、抽帧器、OCR、收藏 App 或 RAG 系统。

## 首个扩展验收

[media：补回视频画面](media.md) 的旧 OCR 路线已完成首个真实扩展验收，见[历史记录](../../docs/media-validation.md)。新默认路线只安装 summarize 抽帧，识读复用宿主多模态能力或用户明确指定的视觉工具，不默认安装 Tesseract、语言包或视觉模型。

2026-10-07 在 macOS arm64 验证了新固定锁首次安装、复跑、旧 OCR 运行目录只复用不卸载，以及一条真实视频的 6 帧抽取。结果为 SourceEnhancement v2 `partial`，每帧 `vision.pending`；这证明抽帧配方可用，不证明已经看图、保存完整增强或新会话召回。此外，复用另一条来源已有 7 个抽样帧中的 1 帧，通过用户明确指定的 Qwen 视觉工具实际识读、维护端核对、v2 追加保存、更新索引和独立新会话回读，返回原链接、原帧及 04:43.17 时间戳。模型额外猜测的游戏名已排除，仅保留核对过的标签。它是这一限定组合的闭环验证，不是新抽出的 6 帧已全部识读，也不是新视觉路线的微信验收；完整范围见[本轮矩阵](../../docs/v0.2-validation.md)。

[PaddleOCR](paddleocr.md) 暂为可选候选，不默认安装。只提升经过实际验收的组合，不将候选项目一起标为兼容。

通用母项目不要求 OpenClaw；宿主兼容只决定 Agent 怎样发现 Skill、调用工具和访问知识库。它与“选择哪个第三方项目补能力”是两个维度。
