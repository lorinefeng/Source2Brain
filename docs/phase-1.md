# 第一阶段验收记录

日期：2026-09-29。运行端为常驻 Mac mini，维护端为 MacBook。本文只保留可公开的结论；原始媒体、运行日志、模型响应、微信会话标识和认证配置保留在运行主机私有目录。

## 实施结果

| 验收项 | 实测结果 |
| --- | --- |
| 独立运行环境 | Node 26.8.2 + OpenClaw 2026.9.6，独立 source2brain profile |
| 对话模型 | 从运行主机已有 Hermes provider 导入，通过实际调用确认使用 `deepseek-v4.1-flash`，无模型回退 |
| 采集 | 用户提供的两条小红书短链，均在 Mac mini 通过 Agent Reach/OpenCLI 取得正文与视频 |
| 本地转写 | 复用既有 Paraformer/VAD/标点模型，产生约 2001 字与 351 字的真实 ASR 文本 |
| 知识整理 | OpenClaw Agent 实际读取原文/转写，生成摘要、逐字引文、推断和建议，执行校验与保存 |
| Markdown 存储 | 两条完整来源，`verify` 无问题，笔记与保存时内容一致 |
| 语义索引 | 官方 llama.cpp provider + EmbeddingGemma 300M Q8；实际 embedding probe 成功，hybrid 检索命中两条来源 |
| 新会话召回 | 新建独立 session，以自然语言提问，不提供标题、链接、笔记路径或答案；Agent 调用 memory_search/read 并返回正确出处 |
| 微信输入 | 本人扫码登录后，从微信真实发送验收链接；正确触发 source2brain Skill |
| 微信处理 | 完成重采集和本地转写，发现来源已存在，保留已有笔记，并执行来源检索 |
| 微信送达 | 用户在手机端明确确认收到完整「收藏完成」摘要 |
| 常驻运行 | 用户级 `ai.openclaw.source2brain` LaunchAgent 已加载，Gateway health 成功 |
| 安装复跑 | 引导脚本在同一运行主机复跑，复用运行时并备份、更新 Skill |

首次写入两条来源通过 CLI 驱动同一个 OpenClaw Agent 完成。随后微信验收使用其中一条已保存来源，因此验证的是重复收藏分支，**没有将这次微信测试记为新来源首次写入**。新会话召回通过独立 CLI session 验证；没有以同一聊天的上下文记忆冒充跨会话检索。

## 自动检查

13 项 Node 测试通过，覆盖：

- URL 识别、平台 ID 归一、非小红书目标拒绝。
- 视频缺转写、图文缺图片、虚构引文不能标记完整。
- 原文中的指令作为数据保留，不经 shell 执行。
- 重复发送与人工编辑保护，来源变化显式冲突。
- 并发写入仅发布一套完整文件；partial 不进入 Sources。
- 不向符号链接目标写入来源。
- 新旧 Agent Reach 体检差异、上游错误标题、登录失败与媒体失败降级。
- 外部命令超时、工具 JSON 格式变化。

Skill frontmatter 校验、Node/Python/Bash 语法检查通过。完整工程没有 Node 第三方运行依赖；语音转写的 Python 环境是可替换的部署依赖。
