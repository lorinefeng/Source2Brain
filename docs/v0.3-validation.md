## 发布规则

只有全部关键验收通过才发布非预览 v0.3.0，并标为最新。未完成时保留候选包与明确缺口；公开说明不把 CLI、受控注入或发送工具成功升级为手机收件。

## 实测发现与修复

- 小红书当前笔记结构化状态的视频流采用新编码键，旧的仅 h264 提取会遗漏视频。任务采集改为当前笔记内遍历 MP4 流，校验视频类型；视频找不到流时暂停，不能把封面当作图文完成。CDN 的 HTTP 原地址只在同一已观察官方主机升级为 HTTPS，禁止明文下载或放宽域。
- 既有 ASR 使用 Python 3.9；哈希采用分块读取，不强迫升级共享 Python。真实生成的无音轨 MP4 返回 NO_AUDIO、退出 1，未生成虚假转写。
- 文本模型首次整理没有提升音频来源 status，协议检查正确拒绝 INCOMPLETE_SOURCE；修正整理结果后保存成功，原采集、转写均未重做。
- 真实图像识读复用了现有独立视觉工具，未修改主对话模型。新增事实仍需原帧核对；本轮两帧恢复验证没有生成完整视频增强成功宣称。
- 原知识与配置保护核对、故障注入脚本、模型工具轨迹及运行回执均在本地私有验收目录，未进入仓库或分发包。

## 微信恢复的核对细节

- 两次 `/new` 的实际 reset 事件分别先于继续任务和来源回顾，宿主虽保留同一对话存储 ID，模型上下文已重置；任务按稳定可信路由复用，不依赖上轮聊天上下文。
- 恢复阶段实际执行本地 embedding 索引和 memory search，再以 Source2Brain read 核对；最后的新会话回顾采用文件查询与原笔记回读。这两个检索层级分别记录。
- Agent 曾把“测试库未加入索引”解释成原失败的原因。原错误实际是受控注入，只能确认后来发现并补齐了索引缺口；本轮补充 Skill 与恢复指南，禁止把错误码或后续发现倒推为已经证实的根因。
- 发送不确定场景由适配层注入测试覆盖；未人为制造微信网络故障，也不承诺严格只送达一次。
