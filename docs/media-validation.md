# media 首个真实扩展验收

> 本文保留 v0.1.0 阶段的历史范围与证据，不作为当前安装或清理指令。当前默认视觉路线、真实验收和待办见 [v0.2 验证矩阵](v0.2-validation.md)。历史 OCR 成功不代表新版视觉链路已通过。

日期：2026-09-29。维护端为 MacBook，运行端为常驻 Mac mini。私有视频、链接、作者、会话 ID、完整路径和运行原始输出不写入本公开文档；它们保留在运行端 media-validation 私有目录。

## 结果

已完成：现有视频 → summarize 抽帧 → Tesseract.js 中英文 OCR → Agent 整理 → SourceEnhancement 追加保存 → OpenClaw 索引 → 独立新会话召回。

- 样本 A：抽取 7 帧，原图核对确认有口播未说出的作品处理标签。增强包含两条有逐字 OCR 引文的画面事实，保存后通过新会话找回标签、原链接、秒级时间戳及真实帧文件。
- 样本 B：抽取 6 帧，OCR 技术流程完成，但尚未找到可靠的口播之外新增文字，保留 Pending，不标为完整知识增强。
- 原来源的 6 个文件（两套 artifact、Markdown、receipt）哈希与部署前备份一致。verify 检查两条原来源和一条当前增强均通过，无人工内容被覆盖。
- 旧音频主题检索仍命中原来源，Gateway 健康检查通过。
- 重复保存返回 duplicate；安装复跑返回 reused。部分候选及被拒绝的机器草稿不进入索引。

## 实测环境与接口

Node 26.8.2、summarize 0.24.0、Tesseract.js 7.0.0、chi_sim/eng 语言包各 1.0.0，macOS arm64。使用 summarize 自带 FFmpeg WebAssembly；未安装 Homebrew、原生 FFmpeg、yt-dlp 或新视觉模型。独立 media 运行目录实测约 217 MB，不含原视频和处理产物。

`doctor --pack media` 只读检测；固定安装脚本执行锁文件安装；`enhance` 只提取、产生待审阅结果；`save-enhancement` 将完整补充及附件原子发布。保存回执中的 indexed: false 只表示保存动作没有执行索引，不代表后续索引的实时状态；索引和召回另有运行证据。

整理使用现有 deepseek-v4.1-flash，后续重跑复用已审阅的整理，并逐字复核新 OCR 引文。最终召回使用全新 session，只提出自然语言问题，不提供答案、标题、链接或文件路径；实际工具记录包含 memory_search、read 与文件检查，返回当前持久化增强目录的真实帧路径。当前对话模型没有配置图像输入，原图核对由维护端执行，不能声称运行端模型直接理解了画面。

本轮验证由 CLI 驱动同一 OpenClaw Agent；没有新增微信发送验收，不把它描述为微信端到端测试。

## 发现的问题与修正

1. summarize 内置 OCR 会过滤纯中文行。本包只使用其抽帧接口，中文 OCR 改由 Tesseract.js 提供。
2. 默认多语言初始化出现乱码子语言加载告警。对照试验后固定 tessedit_load_sublangs 为空，只加载显式中英文；修正后的真实烟测识别出“归档 继续做 / Benchmark 42”，无语言加载告警。该参数进入处理身份，重跑版本与原实验版本区分；原版本移至不参与索引的审计目录保留。
3. DeepSeek 第一稿出现引文不能支持的标签和视觉描述。维护端审阅发现后，确认没有人工修改，备份隔离该次新生成草稿，修正后重新发布。由此把“引文存在”和“事实得到引文支持”的区别写入 Skill 和配方。校验器不能自动保证总结语义正确。
4. 首次召回的秒数正确，但模型额外换算的分钟数错误。加入照录秒数、分秒须程序换算的规则；最终独立新会话复测返回正确秒数和帧路径。

## 验证与边界

27 项 Node 测试通过，覆盖既有 13 项回归，以及增强协议、引文、时间戳、附件缺失/篡改、符号链接、并发去重、人工编辑保护、原版本绑定、Pending 晋级、部分 OCR 失败、发布阶段故障、依赖缺失不安装、安装失败恢复、系统临时路径兼容与就绪环境复用。另有真实中英文 OCR、两条真实媒体处理和独立会话召回证据。

仅承诺本次 macOS arm64、已保存小红书视频、抽样关键帧与 OCR 的组合。帧数上限不保证逐秒覆盖，OCR 存在错字，不能声称理解图表关系或动作。其他宿主、操作系统、新来源直接增强、通用安装器、其他能力包与长期稳定性尚未验收。
