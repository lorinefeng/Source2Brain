# 从 v0.2.0 到更容易上手的 Source2Brain

更新：2026-10-12。这里按用户收益安排后续工作；当前实测状态见[验证矩阵](v0.2-validation.md)。v0.2.0 正式交付已验证范围，下面的项目仍未完成。

## 下一轮优先完成

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| P0 | 新默认视觉路线的微信完整验收 | 用一条未入库视频，从微信投递、真实抽帧与多模态看图，到首次保存、完整回复及新会话查回原链接／原帧／时间戳；记录抽样覆盖，核对至少一个口播缺失的画面事实 |
| P0 | 小红书多图与处理回执 | 真实投递一条多图笔记；逐张识读全部图片，保存并手机确认收到。连续投递时，每条来源都有接收提示、完成结果或可执行的失败原因 |
| P0 | 陌生用户的干净安装 | 找两位没有维护者配置的 macOS 用户，只给公开仓库和安装提示；从下载包、校验、复用／补依赖、本人登录到首次保存和独立召回，记录耗时、人工介入和失败。不能以维护者已有环境替代 |
| P1 | 把失败与重试做得更容易理解 | 登录失效、下载中断、无音轨、模型不可用都留明确回执；复跑不覆盖人工笔记、不重复保存、不重复安装。优先验证现有宿主串行处理，确有证据再增加队列 |
| P1 | 扩大样本并检查模型误读 | 覆盖短／长视频、纯口播、课件文字、中英文混排、多图和无文字画面；报告正确事实、误读、遗漏及耗时，不只统计帧数。视觉推断与来源文字分开 |

## 首批用户上手后再做

- **宿主兼容：** 补 Hermes 的新来源全链路；按用户需求选择 WorkBuddy、Codex、Claude Code 等逐个实装，不把文档入口算作通过。微信参考入口仍使用单一 OpenClaw 绑定。
- **第二个能力包：** 优先考虑 MarkItDown 文档配方，用一份真实 PDF 或演示文稿验证安装、转换、来源映射、保存与回读。Karakeep、Anytype 继续保持候选，避免扩展数量先于可用性。
- **平台范围：** 核心 CLI 的 Linux 测试与真实浏览器采集分开；Windows/Linux 的登录、媒体处理和宿主常驻服务另行实测。
- **贡献门槛：** 给第三方配方补标准化样例、版本锁定、失败回执及验证模板，让贡献者交付可复现配方，而不只是项目链接。

通用安装器、独立 RAG 服务和更多存储后端暂不优先。先让首次安装成功、链接处理可靠、保存的知识能在新会话中带着证据用起来。
