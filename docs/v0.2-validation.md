## 安装与保护

安装演练使用独立 profile、知识目录和扩展运行目录，并列出复用的浏览器、模型与 ASR 环境。已有微信绑定只由原 OpenClaw 服务使用；安装演练不登录同一微信账号争抢消息。更新 Skill/指令前备份，出现问题恢复旧版。

原知识、人工批注、模型和平台登录态保持完整。通过原文件哈希与 store verify 检查保护情况。失败、风控、登录失效保留回执/Pending；不生成成功摘要，不以低层测试代替真实验收。

v0.2.0 发布完整 Skill、源码包、校验和与 README 的 60 秒介绍视频；不分发模型、登录态、私人运行配置和原始操作素材。待验收项目见[后续路线图](roadmap.md)，不因本次发布改成已通过。

## 默认视觉路线调整

- 默认采用原生多模态 Agent；本次文本主模型通过用户指定的独立多模态接口识图。二者身份分别记录，不把外部视觉工具能力写成主模型本身支持图片。
- 新 media 安装仅包含抽帧依赖；不安装 Tesseract/语言包，不自动更换主模型，不安装 PaddleOCR 或其他 VLM 权重。
- 历史识字增强不可覆盖。已知错误以不可覆盖的勘误追加；检索命中后通过统一 read 核对有效事实。图片模型也可能误识别，实际原帧检查继续保留。
- 两次 CLI 新会话都能读回当前来源，非微信再次投递。宿主 memory_search 曾被动返回一条 workspace 记忆片段；最终引用来自实际 Sources 文件。新 Skill 要求过滤非当前 Sources 并统一回读，不把旧工作区记忆当来源。

- 本次 OpenClaw 2026.9.6 在文本主模型之外配置了用户指定的 `qwen36-35b-a3b-awq-marlin-128k`，通过原生 `view_image` 实际接收图片；主模型、微信绑定与服务参数保持不变。配置校验与 secrets reload 成功只算配置层，识读结论来自后续真实工具调用。三张旧误识别帧的工具输出分别包含 `18G`、`4.2` 星形评分和 `(210 个评分)`；任务名仅返回“每小时整理图片”，不能据此称完整名称已识读。
- 历史视频 04:43.17 的原帧在不提供目标答案的新会话中，两次均被该视觉工具读出“归档”和“继续做”。工具还加入了没有图像依据的游戏类别与具体游戏名推断，因此维护端 Agent 直接核图后，仅保留这两个标签作为 `vision.text`，`description` 留空；完整原始输出仍保存在 v2 JSON 的 `vision.raw_output`，不进入事实与索引摘录。视觉模型输出不能直接等同于已核实事实。
- 这份 v2 只复用旧 7 个抽样帧中的 1 帧，未重新采集、转写或抽帧；选择模式、原增强身份与选中帧 ID 进入 `parameters.selection`，避免与以后完整识读的处理身份混淆。由于宿主媒体目录限制，使用当前 workspace 的同字节副本送图，原图与输入副本 SHA256 一致。已有转写中精确词“归档”缺失，而“继续做”存在；没有将本轮工作写成重新听完全片。
- v2 的 validate、原子 save-enhancement、统一 read 与增量索引均成功，store verify 为 4 个来源、4 个增强、0 问题；历史来源原有 13 个文件保存前后哈希一致。全新 CLI 会话只收到自然语言问题，没有来源 ID、链接或预置答案，实际通过 `brain search/read` 返回新 v2 事实、原链接、04:43.17 与正确原帧路径，说明仅 1 帧覆盖，并生成明确标注为 Agent 建议的短句。
- 该新会话没有修改知识或配置、没有外发，但并非全程严格零越界：它额外枚举了 captures 文件名及值已遮蔽的 Source2Brain 环境变量名，并写入临时 JSON 解析回读结果。最终答复一处将两个标签都概括为“画面而非口播”过宽，审片只采用“归档”是已有转写缺失的信息这一可核对表述。此项是新 CLI 回读与创作应用验证，不是微信送达或完整视觉理解验收。
